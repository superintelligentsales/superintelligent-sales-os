# Benchmark Research

How to find, judge, and cite benchmarks in the session. Never write a benchmark from memory.

## Contents
- Search method
- Source quality
- Conflicting sources
- Sanity ranges (for rejecting results only)
- How to cite

---

## Search method

1. Build each query from the user's context: stage name, company size or deal size, annual contract or one-off sale, lead source mix, industry, and the current or previous year. Example: "MQL to SQL conversion rate benchmark B2B SaaS mid-market 2026".
2. Run separate searches per stage. One article rarely covers every stage well.
3. Open the source and read the figure in context: what the source calls each stage, the sample, the year. Skip figures quoted second-hand when the original can be found.
4. Prefer sources from the last 12 to 18 months. If only older sources exist, say how old they are.
5. Aim for three or more independent sources per stage. Two is acceptable with a note. One source means "single source, low confidence".

## Source quality

| Tier | What it looks like | How to use it |
|---|---|---|
| 1, high | Stated method, sample of about 100 companies or more, published regularly (independent research firms, industry associations, recurring benchmark studies) | Use as the main range |
| 2, moderate | Large vendor or platform reports drawn from their own customers | Use, and note the possible bias |
| 3, low | Blog posts, infographics, articles with no stated method or original source | Use only to support tier 1 or 2, never alone |

Vendor content written to sell a product is tier 3 even when it comes from a large company.

## Conflicting sources

- Check first whether the sources define the stage differently. If they do, say so and use the one closest to the user's definition.
- If definitions match, give the range across the credible sources rather than an average.
- If tier 1 and tier 3 disagree, follow tier 1.

## Sanity ranges (for rejecting results only)

These are outer limits of what is plausible for B2B selling. They are not benchmarks. Never show them to the user as a benchmark or use them to price a gap. Use them only to decide whether a search result is believable.

| Stage | Plausible range | A result outside it usually means |
|---|---|---|
| Lead to MQL | 1% to 40% (referral and partner leads sit at the top) | Very loose MQL definition, tracking problems, or referral-only data |
| MQL to SQL | 8% to 40% | No real MQL stage, or MQL doing the SQL's job |
| SQL to Opportunity | 20% to 55% | SQL and opportunity defined as the same thing |
| Opportunity to Won | 10% to 45% | Opportunities created very late, or a narrow segment |
| Lead to Won | 0.2% to 5% | Narrow ICP, referral-heavy data, or a definition mismatch |

If a search result falls outside these ranges, look for the reason before using it. If the user's own rate falls outside them, check definitions and data before diagnosing performance.

## How to cite

In the conversion table, give the range and short source names. In the Sources section at the end, list each source: name, publisher, year, link, and tier. If a stage has no credible source, write "no reliable benchmark found" in the table and leave it out of the dollar math.
